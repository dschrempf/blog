# Project summary

## What this is

Source of the personal blog at https://blog.composef.org/. Content is authored in
**Org Mode**, exported to Hugo-flavored Markdown by **ox-hugo**, then built into a
static site by **Hugo** using the [Skeria](https://github.com/dschrempf/skeria) theme.

## Authoring workflow

The Org files in `org/` are the source of truth — **edit those, not the generated
Markdown in `hugo/content/`**. Markdown files are regenerated by ox-hugo from Emacs
and committed alongside the source.

- Each Org post carries its own ox-hugo export config in its header keywords, e.g.
  `#+hugo_base_dir: ../../hugo`, `#+hugo_section: Coding`, `#+hugo_categories: Coding`,
  `#+hugo_type: post`, plus `#+title`, `#+date`, `#+description`, `#+keywords`.
- `#+hugo_section` determines which `hugo/content/<Section>/` directory the post lands in.
- `#+hugo_draft: true` marks a draft (excluded from production build).
- Posts live in topic dirs (`org/coding/`, `org/emacs/`, `org/linux/`, `org/music/`)
  and are named `YYYY-MM-DD-Title.org`. Top-level pages (`about.org`, `links.org`,
  `privacy.org`, etc.) export to the site root and define menu entries via `#+hugo_menu`.
- Export from Emacs (ox-hugo): `C-c C-e H H` for the current subtree/file. There is no
  command-line export step in this repo — Markdown regeneration happens in Emacs.

## Build & deploy

```
./deploy ["optional commit message"]
```

`deploy` is a [magix](https://github.com/dschrempf/magix) script. It runs `hugo` in
`hugo/`, then commits and pushes **two** repositories:

- `hugo/public/` — a git submodule pointing at `dschrempf/dschrempf.github.io` (the
  published HTML).
- the repo root itself — the Org + Markdown source (`dschrempf/blog`).

To build/preview without deploying, run `hugo` (or `hugo server -D` for drafts) from
inside `hugo/`.

## Submodules

`.gitmodules` defines two submodules — `hugo/public` (published site) and
`hugo/themes/skeria` (the theme). After cloning, run
`git submodule update --init --recursive`.

The Skeria theme is checked out and developed in place under
`hugo/themes/skeria/` — theme changes are made there directly (it tracks the
`dschrempf/skeria` repo), not in a separate clone.

### Theme assets

The theme separates authored from vendored assets:

- **Authored by us** — `hugo/themes/skeria/assets/css/{skeria,fonts}.css` and
  `assets/js/search.js`. Edit these directly.
- **Vendored (downloaded)** — `assets/vendor/css/` (Font Awesome), `assets/vendor/js/`
  (jQuery, Fuse, mark.js, MathJax), and `static/webfonts/*.woff2` (FA icon fonts plus
  the Inter/Lora/JetBrains Mono variable fonts). Don't hand-edit these.

Refresh all vendored assets with `hugo/themes/skeria/update-vendor.sh`, which downloads
pinned versions from [jsDelivr](https://www.jsdelivr.com/) (one CDN serving both the
JS/CSS libraries and the `@fontsource` fonts). The script is the authoritative manifest
of what's vendored; versions are pinned at its top. Subresource Integrity hashes are
computed by Hugo's `fingerprint` at build time, so none are stored. After running it,
rebuild with `hugo` and review the diff.

## Layout notes

- `hugo/config.toml` — site config: permalinks (`/blog/:year/:month/:day/:title/`),
  `categories` taxonomy, syntax highlighting (tango, `unsafe` goldmark for raw HTML),
  and the main menu.
- `org/static/` and `hugo/static/` mirror static assets (cv.pdf, favicon, gpg key, etc.).
- `org/coding/src/` holds source files (`.hs`, `.cpp`) included into posts; copies land
  under `hugo/static/ox-hugo/` and `hugo/public/ox-hugo/` on export.
- Org posts embed raw HTML via `#+begin_export html` blocks (the about page social
  icons, gravatar, etc.) — `unsafe` goldmark rendering is required for this.
